# Flow

A sequence: *somebody joins a list, wait two days, send this*. What
`GET /flows` and `GET /flows/{id}` answer with.

<FlowFields />

## `paused` is not `cancelled`

<Callout type="warning">
A paused flow takes nobody new and **keeps everyone already inside it**. Their
timers keep running; they resume where they were when it is switched back on.
</Callout>

Which means a flow can be `paused` and still have live runs, and a dashboard
that renders paused as stopped will contradict what the seller's customers are
actually receiving.

## `steps` is a shape, not a definition

The ordered node list, each `{ id, kind }`. It is enough to see what a flow
does and to resolve a run's [`currentStep`](/objects/flow-run) to a position
in it.

The node bodies — subject lines, timer lengths, the segment a filter matches —
are deliberately not published. That shape is the contract between the builder
and the runner and is ours to change; a consumer rebuilding "what this flow
does" from it would be reimplementing a parser against a moving target.

## `runs` is null on the list

Counting who is inside a flow aggregates a table that grows with every contact
who ever entered one. A page of twenty-five flows should not pay for
twenty-five such counts, so the list omits them and `GET /flows/{id}` carries
them for the one flow being looked at.

`live` is queued **plus** waiting: both are people still inside the sequence,
and the only difference is whether a timer is currently running.
